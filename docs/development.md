# 开发规范

状态：开发基线，2026-10-22。适用于人工开发、AI 编码与外部贡献。

## 开始修改前

1. 阅读根目录 [AGENTS.md](../AGENTS.md)、[架构方案](architecture.md)、本文、[CI/CD 规则](ci-cd.md) 和 [迭代记录](iterations/README.md)。继续阅读变更目录中的局部规则。
2. 查看工作区状态，确认当前任务、已有修改和模块边界。保留他人的未提交工作。
3. 明确本次要交付的行为、验收方式与影响范围。小任务直接实现；跨模块或破坏性变更先记录设计决定。
4. 只提交与任务相关的改动。避免顺手重构、批量格式化和无理由升级依赖。

文档中的计划不等于已经实现；不得把未执行的检查、性能目标或尚未实现的功能写成完成状态。

## 工具与基础约定

- 采用 TypeScript；后端使用 NestJS + Fastify，前端使用 React + Vite。
- Node.js 基线为 24 LTS，包管理器使用 pnpm。实际版本由仓库运行时配置和根 `package.json` 的 `packageManager` 固定，CI 与本地保持一致。
- 提交锁文件。CI 使用 `pnpm install --frozen-lockfile`；升级依赖必须同时说明原因、兼容性及验证结果。
- 根 `pnpm check` 是统一验收入口。文档阶段检查文档和仓库规则；加入业务代码后必须覆盖受影响的静态检查、类型检查、测试及构建。
- 新增业务包时同步接入 `lint`、`typecheck`、`test`、`build` 和根检查入口。不得用空脚本、`echo`、`|| true` 或无条件跳过伪造通过。
- 尚未建立的命令须标注为待实现，不把未来命令当成当前可运行步骤。首次加入代码时同步落地相应工具配置。
- 自动格式化与静态规则由仓库配置执行，不在单次修改中引入第二套风格。标识符统一英文，说明文档可使用中文。

首次加入 TypeScript 业务代码时，基础配置启用 `strict`、`noUncheckedIndexedAccess` 和 `exactOptionalPropertyTypes`。外部输入使用 `unknown` 并校验，避免用 `any` 或类型断言绕过边界。ESLint 同步检查未处理的 Promise；捕获异常后必须处理、转换或重新抛出，不能静默忽略。

异步 I/O 不阻塞主线程。数据转换、模型处理等 CPU 密集任务按测量结果放入 Worker 或后台任务，并明确取消、超时、并发和清理规则。

## 模块边界

- 场景文档、组件协议、主题协议是共享契约。它们保持轻量，不依赖 React、NestJS 或具体渲染实现。
- 编辑器负责交互；播放器负责展示；场景内核负责状态与命令；渲染器负责绘制。业务状态不得藏在渲染对象中，逐帧动画不得依靠 React 状态更新驱动。
- 二维、图表、三维通过适配器接入。组件通过注册接口声明属性、数据、事件和主题能力，不跨模块访问内部实现。
- 主题提供样式、素材及效果配置，布局与数据权限归底座。代码扩展走独立扩展机制，按安装和兼容规则加载。
- NestJS 按业务划分模块，使用公开服务接口协作，禁止循环依赖和跨模块直接操作私有存储。仅导出需要共享的服务。
- 控制器处理请求边界，服务执行用例，数据访问层处理持久化。DTO 在服务端执行运行时校验，限制字段、尺寸和取值；不能只依赖 TypeScript 类型。
- 使用 Fastify 适配的插件与请求接口，不直接引入依赖 Express 的中间件。适配器差异应由集成检查覆盖。
- 数据连接器、模型供应商和存储适配器遵守各自统一接口，供应商差异留在适配器内。禁止把某家模型字段扩散到核心领域模型。

## 场景、数据和版本

- 人工编辑和 AI 修改都使用统一场景命令，先校验再提交。禁止 AI、面板或插件绕过命令直接修改底层文档。
- 一组关联修改应作为原子操作提交，具备撤销依据。异步生成结果应用前校验目标场景版本，冲突时重新读取并处理，不能覆盖更新的用户操作。
- 场景文档、主题包、组件协议包含版本。对外协议或存量文档不兼容时，提供迁移、失败提示和回退办法；保留旧数据样例用于验证。
- 编辑草稿与发布快照分开；发布引用固定的主题、组件和资源版本，避免升级改变已发布大屏。
- 数据查询与画面解耦。刷新周期由配置控制，统一处理超时、重试、并发上限及销毁后的任务清理。
- 数据库结构变更使用迁移文件，不手工修改线上结构。删除或重算数据前明确兼容策略、备份和恢复方式；不可逆迁移须显式说明。

## 安全与 AI 边界

- 数据库密码、模型 API Key 和其他凭据只保存在服务端，不进入浏览器包、场景文档、主题包或 Git。示例文件只放占位符。
- 日志和异常默认脱敏，不记录密码、授权头、连接串或完整敏感数据。记录请求标识、耗时和必要错误信息以便排查。
- 权限在服务端执行。查询、汇总、AI 工具、预览、导出及缓存复用均遵守同一权限范围，行过滤先于统计汇总。
- 缓存键必须区分影响结果的用户或角色权限、数据源、查询参数和权限版本。权限变化后使旧缓存失效。
- AI 只能调用当前用户获准的工具。来自数据源、上传文件、组件说明和模型返回的内容均视为不可信数据，不能覆盖系统规则或自行授予权限。
- AI 工具参数进行结构化校验；数据库查询使用绑定参数、受控查询能力和受限账号。限制执行时间、结果行数与资源消耗。
- 外部数据源 URL、文件导入和扩展安装必须检查访问边界及资源限制。可执行扩展仅由有权限的管理员安装，不因导入普通主题自动执行未知代码。
- 新增接口检查认证、授权、输入校验和错误脱敏。通用接口错误不返回堆栈与内部凭据。

## 验证要求

按风险选择验证，测试应证明用户行为、边界和回归问题，避免只复述实现步骤。

| 修改内容               | 必须覆盖的验证                                                 |
| ---------------------- | -------------------------------------------------------------- |
| 纯文档、流程规则       | 文档链接、格式、配置有效性；不要求运行尚不存在的应用测试       |
| 场景命令、撤销、迁移   | 前后状态、非法输入、撤销结果、旧版样例兼容                     |
| 查询、权限、缓存、导出 | 越权拒绝、过滤后汇总、权限隔离、缓存失效                       |
| NestJS 接口、连接器    | Fastify 实际请求链路、DTO 校验、超时与错误处理                 |
| AI 修改与工具调用      | 模拟供应商结果，覆盖参数错误、工具拒绝、版本冲突和部分失败     |
| 拖拽、主题、二维/三维  | 相关交互或渲染验证；视觉变化附截图，性能变化记录环境与数据规模 |
| 构建、依赖和发布配置   | 冻结锁文件安装、检查及构建；工作流变更执行工作流静态检查       |

日常 CI 不依赖真实模型费用、生产数据库或外部私有凭据。真实服务测试单独启用并说明所需环境。已有检查通过后，只有新变更或未解决风险才需要重复或扩大验证。

## Git、评审与交付

- `main` 保持可用；从最新 `main` 创建短期分支，如 `feat/scene-commands`、`fix/query-scope`、`docs/contributing`。不增加长期 `develop` 分支。
- 使用 Conventional Commits，例如 `feat(scene): add group command`。提交按可理解的变化拆分，禁止混入凭据、生成缓存和无关文件。
- 通过 PR 合入。描述实际问题、最终行为、验证结果及限制；不把未运行的测试标为通过。涉及视觉、迁移或协议时附相应证据。
- 当前按用户确认采用单人维护：通过 PR 和必需检查，审批人数为 0，由维护者自审并手动合并。有能够独立评审的协作者后，改为至少一名非作者批准，并在新代码提交后撤销旧批准。不得用日常 bypass 或 CI 自动合并代替这些规则，见 [GitHub 设置](github-setup.md)。
- 使用 squash merge，保持主线历史清晰。PR 标题按 Conventional Commits 编写，用作合并提交标题。
- 发布、权限配置及受保护环境遵循 [CI/CD 规则](ci-cd.md)。工作流不自动替维护者决定发布或合并。

每次完成迭代，同步行为相关文档与迭代记录：写明实际完成内容、检查证据、遗留问题和下一步。原有记录保持可追溯，修正记录时注明原因。
