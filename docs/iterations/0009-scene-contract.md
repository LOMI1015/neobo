# 0009：二维场景契约与请求校验基础

- 日期：2026-10-23（Asia/Shanghai）
- 状态：已完成（统一 review、干净构建和隔离开发验收通过）
- 关联：[ADR 0003](../decisions/0003-scene-contract.md)

## 目标

按用户确认的文字、矩形和组合范围，先提供轻量场景文档、结构校验及真实请求边界，为统一命令和编辑器建立基础。

## 实际变化

- 新增 `@neobo/scene`，直接声明已有 Zod 4.6.7，类型由同一校验规则推导；共享包不依赖 React、NestJS、数据库或具体渲染器。
- 第一版明确文档/组件版本、二维变换、有序根节点与组合子节点；严格拒绝未知字段、未知版本、重复 ID、多父、缺失引用、孤立环、不可达节点及解析上限违规，不修改原输入。
- 保留第一版 JSON 样例和不支持版本的回归样例；仅拒绝未知版本，未虚构迁移。
- API 的薄 `SceneDocumentPipe` 复用共享入口，非法请求使用既有安全 400；通过测试专属 Nest 控制器验证实际 Fastify 链路，不新增生产场景接口。
- 共享包导出 ESM/声明，根检查先构建再执行其他三类检查；根开发入口先构建场景包，再共同监听共享包和前后端，完整接入检查与锁文件。

统一验收使用无 `node_modules` / `dist` / 个人 `.env` 的隔离快照。首次默认离线安装因临时文件系统切换到空 store 而失败；显式指定既有 store 后，冻结锁文件安装成功，再执行完整检查。通过哈希比较确认最终非文档文件与已验收快照一致。

所有试验只使用合成配置和临时端口；本次创建的开发进程、日志和隔离目录在交付前清理。原有开发服务和个人配置保留。本次未修改工作流，未额外运行本地 actionlint；远端 CI 以推送后结果为准。

## 遗留问题

- 本次提供二维协议，不代表已经实现文字/矩形渲染、组合交互、组件注册器或完整编辑器。
- 未实现场景存储、权限、发布快照、格式迁移、三维、主题、数据绑定与动画；仍保留在路线图。
- 解析上限仅用于资源保护，不代表性能预算或经过测量的承载规模。
