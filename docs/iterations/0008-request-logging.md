# 0008：统一 API 请求日志与错误边界

- 日期：2026-10-23（Asia/Shanghai）
- 状态：已完成（多 agent 并行实现后，统一 review 与本地验收通过）。
- 关联：[ADR 0002](../decisions/0002-logging-and-audit.md)

## 目标

按路线图优先落地请求日志基础，验证服务端请求标识、错误脱敏、并发上下文和资源释放，再继续场景契约。

## 实际变化

- NestJS 与 Fastify 共用同一 Pino 实例及输出；直接声明已有 Pino 10.4.0，新增仅供开发显示的官方 `pino-pretty` 13.2.0，生产不加载开发格式化器。
- 服务端为请求生成 UUID，经 `X-Request-Id` 返回，忽略外部同名头；AsyncLocalStorage 关联异步服务事件，并发请求不串号。
- 统一异常响应包含稳定 `code` 和 `requestId`；普通请求只输出一条完成摘要，5xx 另有一条受控错误详情；连接中断记录取消，不伪造尚未发送的状态码。畸形 URL 和超长参数也经过独立错误边界，禁止默认回显原始路径。
- 运行日志仅允许固定事件和有界平面字段；不输出请求正文、原始 URL、查询参数、凭据、任意异常正文或堆栈，子日志不能关闭该限制。
- 复用原生异步输出的 64 KiB 缓冲上限、丢弃计数与固定降级提示，关闭有时限；艺术字仍只在监听成功后输出一次。移除旧 ConsoleLogger 入口，同步相关文档和过时引用。
