# 0010：场景原子命令与启动日志降噪

- 日期：2026-10-23（Asia/Shanghai）
- 状态：已完成（并行开发、统一 review 和验收通过）
- 关联：[ADR 0004](../decisions/0004-scene-commands.md)

## 目标

解决启动终端多次显示相同“框架运行事件”的问题，并按既有二维契约完成下一步统一命令、修订号冲突检查和撤销/重做内核。

## 实际变化

- NestJS 常规初始化和原生 Pino/Fastify 普通 info 降为 debug，默认保留受控业务摘要和警告/错误。通过启动前环境变量 `LOG_LEVEL=debug pnpm dev` 开启诊断，只输出白名单来源，不回显原始消息、异常或任意 context；无效级别在分配日志资源前拒绝。
- 共享包增加添加、部分更新、删除、移动四类操作。严格校验场景标识、基础修订号、操作数量及每步结构；副本上整批成功后只递增一次修订号，任一失败不修改输入。
- 按用户确认，删除组合会删除全部子树，撤销恢复全部内容及顺序。移动支持树结构和同级排序，父局部变换保持显式数值，不提前实现视觉分组换算。
- 单人内存历史提供 execute、undo、redo、current、可用性查询与 clear；失败保留重做，成功分叉清除重做，所有文档返回值隔离。过去/未来快照合计受条数和 UTF-8 JSON 预算约束，当前文档单独受同一字节上限约束。
- 交叉 review 发现并修复修订号进位使精确容量下的撤销失败问题；计量统一预留最大安全整数位数，覆盖 9→10、99→100 的撤销和重做。
- 增加 `SceneCommandBatchPipe`。真实 NestJS + Fastify 测试模块接入同一历史内核验证原子失败、并发冲突和撤销/重做，默认生产模块仍不提供场景写入路由。
- 原文档校验实现仅移到内部模块并复用规则，第一版协议和既有样例保持兼容；不新增依赖或修改工作流。

## 遗留问题

- 本次交付共享内核，不包含画布界面、视觉分组/拆组、渲染器或 AI 调用。
- 内存会话的同步修订检查不是跨进程并发保证；持久化时仍需授权和数据库条件写入/事务。未实现身份、场景存储或发布快照。
- 历史容量仅是资源保护，UTF-8 计量不等于 JavaScript 堆内存或性能预算；到达最大安全整数后执行、撤销、重做均明确拒绝。
- `LOG_LEVEL` 从日志初始化前的进程环境读取，不从根 `.env` 加载；开启 debug 也不输出原始框架正文。
