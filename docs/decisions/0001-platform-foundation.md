# ADR 0001：平台基础架构

- 状态：已接受（架构方向，尚未实现）
- 日期：2026-10-22
- 范围：首版产品模型、前后端边界、扩展与数据访问
- 关联：[目标架构](../architecture.md)

## 背景

neobo 面向开源自托管，需要通过 AI 对话和鼠标共同构建包含丰富动画、三维场景的数据大屏。用户要求自由组合原子元素，并将丰富视觉表现放入独立主题包，使基础平台与主题可以持续独立迭代。

后端将逐步包含权限、数据连接器、查询、版本发布、扩展及 AI 调度。开发前需要统一模块边界，避免编辑器、AI 和插件各自实现不同的场景和授权逻辑。

## 决策

1. **采用 TypeScript 模块化单体。** 前端使用 React + Vite，后端使用 NestJS + Fastify；耗时任务在独立后台进程执行。NestJS 管理模块与业务依赖，Fastify 提供 HTTP 处理。暂不拆分微服务。
2. **采用原子元素、组合、场景模型。** 自由白板提供默认简洁外观，不以内置布局模板作为核心生成单位；用户组合可保存和拆分。
3. **采用版本化场景文档与统一操作指令。** AI 与人工编辑共用校验、操作、撤销和修订号检查。发布形成固定依赖版本的快照，播放器与编辑器独立打包。
4. **功能内核与视觉主题分离。** 底座提供布局、数据、渲染、事件和动画机制；主题提供样式变量、素材和效果配方。新算法通过代码扩展提供，主题可声明依赖；一期代码扩展由管理员安装并承担信任责任。
5. **二维与三维统一逻辑、分别绘制。** 初选 DOM/SVG、ECharts、three.js；React 负责编辑界面，播放内核负责逐帧动画。三维共享渲染器作为优先验证方向，最终合成方式由原型确认。
6. **数据访问统一进入服务器查询层。** PostgreSQL 存储平台数据，Redis + BullMQ 支持缓存与任务，素材采用本地文件并提供 S3 兼容接口。数据库/API 优先，文件导入在一期后半段。权限先于汇总执行，缓存区分有效授权范围。
7. **AI 使用统一供应商适配层与受控工具。** 以 AI SDK 为基础，保留 neobo 自己的能力描述、限制及错误处理；模型只通过当前用户有权执行的工具操作。

## 考虑过的替代方案

| 方案                                       | 未采用的原因                                                                 |
| ------------------------------------------ | ---------------------------------------------------------------------------- |
| 直接使用 Fastify 组织全部后端业务          | 可行，但需自行建立并持续维护复杂模块的统一约定；本项目优先采用 NestJS 的结构 |
| 起步即微服务                               | 部署、联调和权限传递成本较高，尚无实际负载支持拆分                           |
| AI 直接生成整页 HTML/React                 | 难以稳定保持可编辑性、撤销、主题切换和组件级数据权限                         |
| 依靠预设布局模板生成看板                   | 与自由白板、原子组合的产品方向不符                                           |
| 将主题和具体表现固化进内核                 | 主题变化需要频繁修改内核，不利于社区独立迭代                                 |
| 全部内容统一放进一个 Canvas/WebGL 绘制系统 | 对文字、表格、图表和浏览器交互提出额外实现成本；先验证混合绘制的收益与限制   |
| 浏览器直接连接数据库或调用模型供应商       | 无法统一保管凭据和执行授权，也不利于查询复用与调用治理                       |

## 代价与约束

- NestJS 增加框架约定及样板代码；Fastify 插件、上传和流式接口需按实际适配器验证，不能直接照搬 Express 中间件。
- 原子化需要稳定的元素、属性和组合协议；自由度越高，编辑交互与 Agent 的检查责任越重。
- 版本化场景、主题和扩展带来兼容与迁移成本；发布回退还依赖旧版本资源的保留。
- 混合渲染带来图层、透明度、坐标投影、拾取与资源释放问题，必须通过真实场景验证。
- 行级与列级过滤限制了任意查询的自由度；无法可靠授权的查询应拒绝执行。
- 多模型接入需要能力分级，不能保证所有供应商效果与速度相同。
- 管理员可信扩展不等于第三方代码沙箱，不能据此允许普通用户上传并执行任意代码。

## 后续验证与变更条件

先用同一张包含图表、三维、跟随标签和动画的场景验证编辑/播放、主题切换、授权查询及 AI 局部修改。记录目标硬件、1080p/4K、长时间播放和模型调用结果，再确定性能预算与绘制细节。

出现可重复的技术限制或负载证据时，可通过后续 ADR 替代具体选择。开源许可证、版本号策略、GitHub 保护规则和 CI/CD 流程不在本 ADR 的决策范围，由对应规范单独管理。
