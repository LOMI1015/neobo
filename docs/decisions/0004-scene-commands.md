# ADR 0004：原子场景命令与单人编辑历史

- 状态：已接受（实施及验证见迭代记录）
- 日期：2026-10-23
- 范围：共享场景命令、修订号检查、撤销/重做和请求校验
- 关联：[ADR 0003](0003-scene-contract.md)、[目标架构](../architecture.md)

后续 [ADR 0010](0010-scene-themes.md) 新增 `scene.theme.set`，继续复用本 ADR 的原子批次、修订与历史约束；本文保留首批节点操作决策。

## 背景

二维文档已支持文字、矩形和组合，但编辑器与 AI 仍缺少统一的状态修改入口。架构要求关联修改整体成功或失败，旧修订不能覆盖新操作，撤销与重做应有可验证的依据。用户确认删除组合时删除全部子元素，撤销时整体恢复。

当前没有场景持久化、身份与项目授权或画布界面。本次交付可被前后端复用的同步纯逻辑，不提前创建可写入的生产场景接口。

## 决策

1. 在现有 `@neobo/scene` 内增加命令与历史模块，复用 Zod 和已有文档校验。文档格式仍为第一版；旧样例保持可读，不新增状态库、通用补丁协议或框架依赖。
2. 命令批次包含 `sceneId`、`baseRevision` 和 1–100 项有序 `operations`。场景标识必须匹配，基础修订必须等于当前修订。所有参数来自 `unknown`，严格拒绝未知字段、隐式转换和未定义的操作。
3. 首批只提供 `node.add`、`node.update`、`node.remove`、`node.move`，围绕已有节点类型工作，不接受任意文档替换。调用者显式提供节点 ID，不自动生成标识或时间。
4. 每个操作和最终结果都须符合文档约束。批次在独立副本中顺序执行，任何一步失败都不提交；全部成功只增加一次修订号，并形成一步历史。即使内容与之前相同，成功批次仍是一次提交；空批次拒绝。
5. 撤销/重做恢复完整内容、父子关系和顺序，修订号继续递增，不回退到快照的旧修订。执行、撤销、重做都检查场景和基础修订；安全整数耗尽时明确拒绝，状态不变。
6. 历史由封闭会话持有，调用者只能通过公开方法操作。初始输入、查询结果和成功结果相互独立，修改返回对象不能污染当前状态或历史。失败操作保留当前状态和重做栈；成功的新批次清空重做栈。
7. 使用有界文档快照，而非先引入通用差异或协作框架。默认最多保留 100 个快照，过去和未来合计 UTF-8 JSON 计费不超过 16 MiB；调用方可调低，不能超出这两个保护上限。计费统一为修订号预留最大安全整数的 16 位空间，避免修订号从 9 增到 10 等位数变化使撤销失效。初始化与当前结果也必须能容纳于单个快照预算，容量不足明确失败，不把无法撤销的修改伪装成普通成功。
8. 快照先保留最近的可逆一步；执行新批次时从最早的过去历史淘汰，撤销/重做时优先淘汰远端历史。预算是存储计量与资源保护，不等于 JavaScript 堆内存测量或画布性能预算。`clear()` 只释放历史引用，不改变文档或修订。
9. API 增加薄的 `SceneCommandBatchPipe`，复用共享参数校验，非法输入沿用现有安全 400。测试专属 Nest 控制器和内存会话验证真实 Fastify 请求、冲突 409、原子失败和撤销/重做；生产模块不挂载这些测试路由。

## 操作语义

| 操作          | 参数及效果                                                                                                                         |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `node.add`    | 提供完整 `node`、`parentId` 和 `index`；`null` 表示根列表，组合父节点必须存在；新组合的 `children` 必须为空                        |
| `node.update` | 提供 `nodeId` 和非空 `changes`；仅允许部分变换、可见性和文字内容；`text` 只用于文字节点，空变换拒绝                                |
| `node.remove` | 提供 `nodeId`；删除节点及全部后代，移除父列表中的对应引用；撤销恢复整个子树及原顺序                                                |
| `node.move`   | 提供 `nodeId`、`parentId` 和 `index`；用于同级排序或显式修改父节点，索引相对于从原位置移除之后的目标列表；不能把组合移入自身或后代 |

移动到新父节点后保留变换的父局部数值，不承诺画面位置保持。调用者需要在同一批次显式更新变换；视觉分组/拆组的坐标换算与交互随画布验证，不将这层树操作冒充已经完成的视觉分组功能。

失败结果只包含固定错误码与必要的有界操作下标，不回显命令正文、节点文本、未知字段或第三方错误。修订检查与同步提交发生在同一内存会话中；后续持久化必须在授权后使用数据库条件更新或事务实现原子比较与写入，不能把本次测试当作分布式并发保证。

## 复用与取舍

- Zod 严格对象和判别联合继续作为唯一参数定义，类型从规则推导，文档节点规则在包内复用。现有协议实现移到内部文档模块，公开出口保持兼容。[Zod 严格对象与联合](https://zod.dev/api)。
- 历史保存经过校验的纯数据，仅承担当前单人状态的撤销；不包含外部 I/O、权限判断或副作用，因此不需要引入状态管理器、事件存储或实时协作算法。后续出现实际消费者及规模依据后再评估补丁和结构共享。
- 请求适配继续使用 NestJS 的公开 `PipeTransform` 接口。命令参数校验不等于认证或授权，也不代替服务端执行时读取当前修订。[NestJS Pipe](https://docs.nestjs.com/pipes)。

## 后续工作

将命令接入二维画布交互，验证文字/矩形绘制、选择和拖动，再增加保持画面位置的分组/拆组交互。持久化、授权、发布快照和 AI 调用仍需独立实现；编辑器和 AI 都应复用本命令入口。
