# ADR 0003：第一版二维场景契约与校验边界

- 状态：已接受（第一版范围已确认，实施及验证见迭代记录）
- 日期：2026-10-23
- 范围：共享场景文档、运行时校验、NestJS 请求边界与工作区构建
- 关联：[目标架构](../architecture.md)、[开发规范](../development.md)

后续 [ADR 0010](0010-scene-themes.md) 增加可选固定主题引用，旧 v1 文档保持缺省结构；本文保留第一版契约决策。

## 背景

请求日志基础已完成，下一步需要在编写编辑操作之前固定可校验的场景输入。用户确认首批二维元素为文字、矩形和组合。当前没有存量场景、场景保存接口、编辑器或组件注册器；不能把这些目标写成已有能力。

前后端只共享契约与纯逻辑。只靠 TypeScript 无法校验外部 JSON；分别手写 TypeScript 类型和 JSON Schema 又容易产生差异。锁文件已有 Zod 4.6.7，NestJS 已提供自定义 Pipe 扩展接口，可复用成熟规则与框架边界。

## 决策

1. 新建 `packages/scene`，包名 `@neobo/scene`，仅依赖显式声明的 Zod 4.6.7，由校验规则推导 TypeScript 类型。它不依赖 React、NestJS、数据库或具体渲染器。
2. 先定义 `schemaVersion: 1` 的二维文档，包含 `id`、非负安全整数 `revision`、画布宽高、`rootIds` 和扁平 `nodes`。文字、矩形有独立 `componentVersion: 1`；组合只表达层级和变换，不作为组件实现或渲染能力交付。
3. 节点公共字段为 `id`、`transform`、`visible`。变换包含 `x/y/width/height/rotation`；文字额外有 `text`，矩形不添加空属性占位，组合额外有 `children`。第一版不预设样式、主题、三维、数据绑定、任意属性袋或播放状态；这些能力有真实消费者时再扩展协议。
4. 父子关系只有 `rootIds` 和组合的 `children` 一份来源，不重复保存 `parentId`、`zIndex` 或嵌套节点副本。引用数组顺序是同级从后到前的绘制顺序；节点数组顺序只用于存储。每个节点恰好被根列表或一个组合引用一次。
5. 二维坐标以父节点局部逻辑像素为单位，横向向右、纵向向下；旋转单位为角度，正值顺时针，绕节点自身中心。组合不自动布局或裁剪子节点。这里规定数据含义，实际绘制与组合操作留给后续迭代验证。
6. 所有对象严格拒绝未知字段，不转换类型、不填默认值、不删除输入字段。校验成功返回校验产物，不修改原输入；失败只提供固定问题码和安全字段路径，不回显未知键、输入值或第三方错误消息。
7. 结构校验拒绝重复 ID、缺失或重复引用、多父节点、自引用、环、不可达节点、原子元素持有子节点及资源上限违规。空场景、空文字和空组合合法；层级检查采用迭代遍历，不依赖递归堆栈。
8. 当前只接受第一版；遇到旧版或未来未知版本明确拒绝，不伪造迁移或静默丢字段。保存固定第一版样例和不支持版本的回归样例；实际格式升级时必须另加迁移与兼容测试。
9. API 提供薄的 `SceneDocumentPipe`，调用同一共享校验入口并沿用现有安全异常边界。仅用测试专属 Nest 控制器验证 Fastify 真实请求链路，本次不添加未经确定用途的生产场景接口，也不声称已有认证、持久化或权限校验。
10. 共享包输出 ESM JavaScript 和声明文件，业务包通过 `workspace:*` 使用公开出口。统一检查改为先按依赖顺序构建，再执行 lint、typecheck、test，保证干净环境不依赖遗留产物。开发入口先构建共享包，再共同监听场景、API 和 Web，复用现有进程管理器。

## 第一版解析上限

| 项目           | 上限或规则                                                                 |
| -------------- | -------------------------------------------------------------------------- |
| 场景及节点 ID  | 1–64 个 ASCII 字符，首字符为字母或数字，其余允许字母、数字、下划线和连字符 |
| 节点数量       | 1,000；空数组合法                                                          |
| 树层级         | 32；根节点为第 1 层                                                        |
| 画布及节点宽高 | 有限正数，最大 16,384                                                      |
| 节点 x/y       | 有限数，绝对值不超过 1,000,000；允许画布外坐标                             |
| 节点旋转       | 有限数，绝对值不超过 360,000 度；不隐式归一化                              |
| 文字           | 最多 10,000 个 Unicode 码点；空串合法                                      |
| 问题数量       | 最多 20 条；路径仅含已知字段和有界数组下标                                 |
| HTTP 请求体    | 沿用 API 现有 1 MiB 上限，不因共享契约扩大                                 |

这些是当前解析保护，不能当作支持规模、画布性能预算或渲染能力。后续按真实场景与硬件测量调整；公开协议变化需保留可追溯的兼容处理。

## 复用与取舍

- Zod 的严格对象、类型推导和可组合校验减少双份结构维护；仅增加跨节点图约束和安全问题映射。Zod 4.6.7 为 MIT，当前锁文件已有该版本，不升级无关依赖。[官方要求](https://zod.dev/)、[严格对象和校验](https://zod.dev/api)、[许可证](https://github.com/colinhacks/zod/blob/v4.6.7/LICENSE)。
- Fastify 默认 Ajv 配置包含类型转换、默认值和字段清理，不能直接当作本契约的严格解析。NestJS 12 内置 Standard Schema Pipe 也会先递归删除部分字段；本例采用官方 Pipe 接口做必要衔接，保留原始输入并拒绝未知字段，不覆盖框架的内部安全方法。[Fastify 校验](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/)、[NestJS Pipe](https://docs.nestjs.com/pipes)。
- 导出构建产物适配现有 NodeNext API，避免应用编译共享源码时跨越 `rootDir`；先构建也让带类型的 lint 和测试拿到声明文件。暂不为单个共享包引入额外打包器或整套项目引用。[pnpm 依赖排序](https://pnpm.io/cli/recursive)、[TypeScript rootDir](https://www.typescriptlang.org/tsconfig/rootDir.html)。
