# neobo 目标架构

状态：目标架构，2026-10-23。当前已建立开发环境骨架，本文描述的完整看板能力仍按阶段实现。基础决策见 [ADR 0001](decisions/0001-platform-foundation.md)，实施状态以迭代记录和代码为准。

## 1. 定位与原则

neobo 是开源、自托管的 AI 对话式大屏平台，通过浏览器编辑和播放，重点支持大量动效与 three.js 三维场景。

- 以“原子元素 → 组合 → 场景”构建，从自由白板开始，不提供固定布局模板。用户可保存自己的组合并再次拆分修改。
- 底座默认提供可用、简洁的中性外观；丰富样式、素材和效果由独立主题包提供。
- AI 与鼠标使用同一套场景操作，不能分别维护两套状态。
- 数据访问、权限判断和模型调用统一经过服务端；浏览器负责交互与渲染。
- 先建设边界清楚的模块化单体，依据实际瓶颈再拆分服务。

## 2. 技术选择与职责

| 部分           | 选择                           | 职责与约束                                                                |
| -------------- | ------------------------------ | ------------------------------------------------------------------------- |
| 语言           | TypeScript                     | 前后端共享契约；外部输入仍需运行时校验                                    |
| 编辑器         | React、Vite、Zustand           | 工具栏、属性面板、画布交互和编辑状态                                      |
| 二维元素       | DOM / SVG                      | 文字、形状、图片及二维交互；具体绘制边界通过原型验证                      |
| 图表           | ECharts                        | 图表作为可配置数据元素，不承担整个画布                                    |
| 三维           | three.js，初期以 WebGL2 为基础 | 模型、材质、灯光、相机、粒子及空间交互                                    |
| 服务端         | Node.js、NestJS + Fastify      | NestJS 组织业务模块，Fastify 处理 HTTP；集成必须适配实际 Fastify 运行环境 |
| 平台数据库     | PostgreSQL                     | 用户、项目、看板草稿、发布版本、权限、配置与审计信息                      |
| 缓存与后台任务 | Redis、BullMQ                  | 查询缓存、刷新调度、导入等耗时任务                                        |
| 运行日志与审计 | Pino、PostgreSQL 独立审计表    | 请求关联与脱敏已实现；任务关联和持久审计待实现                            |
| 素材存储       | 本地文件 + S3 兼容适配接口     | 模型、纹理、字体、图片、上传文件和扩展包                                  |
| AI             | AI SDK + neobo 模型适配层      | 多供应商调用、能力检测、结构化结果及流式反馈                              |
| 自托管         | Docker Compose                 | 初期部署入口；具体版本与依赖由仓库锁文件固定                              |

初期运行形态为静态前端、主服务、后台任务进程、数据库、Redis 和素材存储。后台进程复用业务与权限规则，不能绕过查询入口直取数据。

## 3. 模块边界

- **编辑器**：选择、拖拽、缩放、吸附、对齐、分组、属性编辑、历史记录及 AI 对话。
- **播放器**：加载发布快照、取数、播放动画和执行交互；独立打包，不携带编辑器代码。
- **共享内核**：场景契约、操作指令、组件注册、主题解析、数据绑定和播放生命周期。
- **服务端业务**：身份与授权、项目与场景、版本与发布、数据源、查询、Agent、素材及扩展管理。
- **后台任务**：定时刷新、导入、资源处理等任务；任务需携带必要的授权上下文并可追踪。
- **适配接口**：模型供应商、数据连接器、素材存储、组件、主题及效果扩展。

前后端只共享稳定契约与纯逻辑。数据库驱动、凭据、模型密钥和服务端授权实现不得进入浏览器依赖。

## 4. 场景文档与统一操作

场景文档是可保存、可校验、可迁移的数据结构，至少包含：

| 内容     | 要求                                                       |
| -------- | ---------------------------------------------------------- |
| 版本信息 | 文档格式版本、场景标识、草稿修订号                         |
| 元素树   | 稳定元素标识、父子关系、类型、坐标空间、变换、可见性和层级 |
| 元素配置 | 组件版本、属性、数据绑定、交互和资源引用                   |
| 三维内容 | 视口、相机、模型引用及空间关系                             |
| 动画     | 时间轴、触发事件、状态和效果引用                           |
| 主题     | 固定版本、公共样式变量、元素级覆盖                         |

当前第一版二维契约支持文字、矩形和组合的数据结构、版本和图结构校验，见 [ADR 0003](decisions/0003-scene-contract.md) 与 [共享包](../packages/scene/README.md)。仅实现协议与请求校验基础，渲染、主题、动画、存储和命令仍按后续迭代推进。

实际数据结果、数据库凭据、模型密钥和逐帧运行状态不写入场景文档。数据绑定引用服务端查询标识，素材使用受管理的资源引用。

鼠标和 AI 都提交标准操作，例如添加、移动、分组、绑定数据、设置主题属性。操作必须经过参数、场景结构和权限检查；一批修改应整体成功或整体失败，失败时保留原文档。服务端检查基础修订号，避免旧结果覆盖新修改。

操作应支持可逆修改与撤销/重做；不能逆转的外部动作不伪装为普通编辑指令。一期按单人编辑设计，出现版本冲突时明确提示和处理，不直接覆盖。多人实时协作不在一期范围。

草稿与发布快照分离。发布快照固定场景、主题、组件及资源依赖版本，正式大屏读取快照；升级前可预览，并保留可回退的旧版本。格式变更需提供迁移或明确拒绝加载，禁止静默丢字段。

## 5. 主题与扩展

### 底座与主题的分工

| 底座提供机制            | 主题提供表现                     |
| ----------------------- | -------------------------------- |
| 元素、组合和布局        | 元素皮肤、装饰与视觉参数         |
| 图表与数据绑定          | 配色、字体、线条和数字样式       |
| 三维加载与材质/效果接口 | 材质方案、环境、灯光和素材       |
| 动画、事件和状态系统    | 入场、呼吸、流光、粒子等效果配方 |
| 加载、兼容与资源管理    | 包清单、资源、效果配置及扩展依赖 |

主题包应声明标识、版本、兼容范围、资源、公共样式变量、效果参数、依赖和 AI 使用说明。强调色、告警色、字体、线宽等变量同时供二维和三维使用。元素属性区分“跟随主题”和“固定值”，切换主题保留用户明确固定的设置。

主题控制视觉表现，不替用户指定布局。缺失的可选效果可以降级；缺失的必需组件或依赖必须报出可定位的错误，禁止展示伪成功状态。

### 配置与代码的边界

普通主题主要由配置、素材和动画配方组成，不获得任意代码执行或数据源访问能力。新算法、新组件、特殊材质通过代码扩展接口提供，主题可声明其依赖。

一期仅允许管理员安装可信代码扩展；这类代码属于部署信任边界，不能声称已经实现任意第三方代码的安全沙箱。包清单、兼容性、资源路径和加载失败必须校验。未来如开放不可信代码，需单独设计隔离环境和受控通信协议。

组件清单应提供属性结构、默认值、数据输入、事件输出、主题变量、生命周期和 AI 说明。组件卸载必须释放监听器、定时器及 GPU 资源。

## 6. 二维、三维与动画

二维与三维共享元素标识、选择、分组、数据绑定和事件规则，分别保留屏幕坐标和空间坐标。三维视口可以和二维信息层组合；跟随模型的标签通过坐标投影定位。

优先验证共享三维渲染器及资源的方案。多视口、遮挡、透明背景、图层混排、拾取和坐标转换需通过原型确定，不能把所有绘制方式强行合成一套未经验证的画布。

动画由播放内核统一调度，时间轴描述先后顺序，事件驱动状态变化。React 不承担逐帧状态更新。数据刷新频率、播放帧率和特效质量分别配置。

性能设计包括局部更新、按需加载、资源复用、减少不可见内容计算、服务器汇总和明确的资源释放。使用同一场景验证 1080p、4K、编辑与播放状态，记录硬件、帧率、交互延迟、首屏、内存及长时间播放结果；具体承载指标在原型后确定。

## 7. 数据、刷新和权限

首批目标连接器为 PostgreSQL、MySQL 和 HTTP JSON；CSV/Excel 导入位于一期后半段。连接器负责连接、发现字段、执行受控查询、标准化结果和错误，不自行实现另一套授权。

查询与组件分离，一个查询结果可绑定多个元素。查询定义包含参数、字段映射、类型、筛选、汇总和刷新策略；业务指标提供名称、计算口径与允许使用的数据范围。

刷新支持全局默认、查询覆盖、手动刷新、暂停，以及超时、重试和最近更新时间。同一有效权限范围内的相同请求可以合并。后台刷新应避免重复调度和失败后无限重试；参数范围及限流规则由服务端控制。

权限至少覆盖项目/看板操作、数据源访问、字段和数据行。执行顺序为：身份识别 → 授权 → 字段与行限制 → 查询/汇总 → 结果返回。图表、Agent、预览和导出共用此入口。

- 数据库连接尽量使用只读最小权限账号；凭据只保存在服务端。
- 不将任意 SQL 当成天然安全的查询接口。受限角色的查询必须能够可靠施加行、列规则；做不到时禁止执行，不能只在浏览器隐藏结果。
- 外部 HTTP 数据同样需要声明可执行的权限策略，不能默认所有用户拥有相同数据范围。
- 缓存键包含数据源、查询、参数和有效授权范围/策略版本；权限变化后失效，不能仅按查询文本复用。
- 日志和审计默认记录操作及追踪信息，避免记录密钥和完整敏感数据。

PostgreSQL 行级策略可用于平台内部数据的附加保护，不能代替外部数据源的查询授权。

## 8. Agent 与多模型

Agent 读取当前场景、选中元素、组件与主题能力、授权数据结构及业务指标；通过受控工具查询数据和提交场景操作。模型生成的操作与普通外部输入一样，必须校验后执行。

流程为：理解意图 → 获取必要上下文 → 规划/生成操作 → 校验 → 应用 → 返回结果。简单修改直接走局部操作，复杂创作按可检查的批次生成；取消、超时和失败不能破坏现有场景。

AI SDK 之上保留 neobo 适配层，显式描述工具调用、结构化输出、流式响应等能力。自定义接口地址与本地模型通过适配接入；兼容某种 HTTP 格式不等于能力完全一致。

工具权限继承当前用户，Agent 无权绕过数据过滤、获取凭据或安装代码扩展。外部数据、主题说明和模型响应都作为数据处理，不能覆盖系统授权规则。

性能优化优先减少调用次数、缩小上下文、批量操作和复用授权查询。记录成功率、耗时、重试和调用费用，并为模型输入、输出、调用轮数和任务时长设置上限。

## 9. 日志与审计

运行日志复用 Fastify 的 Pino，NestJS 使用同一入口；输出逐行 JSON，由部署环境收集和轮转。请求、数据查询、Agent 和后台任务通过受控标识关联，错误在统一边界处理，避免重复记录。默认不记录凭据、业务正文、查询结果或 AI 对话原文。

操作审计单独存入 PostgreSQL，受保护的数据库变更与成功审计同事务；外部副作用采用持久化意图和幂等流程，不假设跨系统原子性。审计有独立权限，不因日志采样或级别开关丢失。运行日志与审计的保存周期和容量按用户确认留到上线前决定。

详细字段、故障处理、浏览器边界和验收见 [日志设计](logging.md)，取舍见 [ADR 0002](decisions/0002-logging-and-audit.md)。当前已实现请求日志基础，任务关联和持久审计仍待实现；集中检索和完整调用链按实际需要接入成熟工具。

当前 NestJS 与 Fastify 共用 Pino，请求标识由服务端生成，通过 `X-Request-Id` 返回；请求摘要和错误边界只记录受控字段。开发终端保留品牌艺术字与模块配色，使用 `pino-pretty` 显示日志，生产输出无色 JSON；操作审计仍待实现。使用方法见 [本地开发](local-development.md#终端输出)。

## 10. 一期范围与验收

| 阶段     | 交付目标                                                                          | 验收重点                                               |
| -------- | --------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 核心验证 | 自由画布、原子元素/组合、图表、三维模型、跟随标签、基础时间轴、两个小型主题验证包 | 拖拽与播放流畅；同一场景切换主题后保留布局、数据和交互 |
| 基础平台 | 数据库/API、刷新、权限、版本、发布、组件接口及文件导入                            | 查询与导出权限一致；发布隔离草稿；可追踪和回退         |
| AI 闭环  | 多模型配置、对话创建、局部修改、主题效果调用                                      | 对话与鼠标交替编辑、检查失败保护、撤销和再次发布       |

完整验收路径：连接数据 → 对话搭建 → 自由拖拽组合 → 添加三维与动画 → 切换主题 → 按权限发布展示。

一期不承诺通用三维建模器、复杂模型编辑、任意第三方代码沙箱、组件市场、全部数据库适配或多人实时协作。

实施前仍需通过原型明确二维/三维合成方案、资源预算和性能指标；通过测试明确不同模型的工具调用质量、受限查询的可执行方式以及长时间播放的资源释放。首版数据源优先级、目标硬件和开源许可证需独立确认，不视为已完成决策。
