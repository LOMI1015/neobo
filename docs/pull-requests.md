# 中文合并请求与 AI 提交流程

本项目托管在 GitHub，合并请求使用 Pull Request（PR）。日常所说的 MR 在这里对应 PR。

## 标题与说明

PR 标题、正文和提交说明使用中文；Conventional Commits 的类型、范围，以及技术名称、代码和命令保留原文。

标题格式为 `类型(可选范围): 中文描述`，描述实际完成的变化。例如：

- `feat(scene): 新增场景分组与撤销`
- `fix(api): 修复数据查询的权限过滤`
- `docs: 完善中文合并请求模板`

保持标题简短明确；使用 squash merge 时，PR 标题作为合并提交标题。标题检查仍使用 Conventional Commits 的技术前缀。

正文使用 [默认模板](../.github/pull_request_template.md)，填写问题与结果、实现要点、验证、影响与回退。按改动规模写清最终结果，删除提示文字，不留下未填写的占位内容。

验证必须包含实际命令及结果。未执行或受环境限制的检查写明原因，不把预期结果、待执行的检查或不存在的远端 CI 写为通过。视觉、权限、协议、迁移或性能变化按需提供对应证据，无关材料无需逐项填写。

CI 会检查标题格式、描述中的中文，以及正文中的实际中文说明；模板标题、注释、代码、网址和勾选清单不算已填写。Dependabot 等机器人的 PR 同样适用，合并前由维护者改写为中文。检查不能判断说明是否准确完整，仍需人工评审。

本地预检可准备事件 JSON 文件，例如 `/tmp/neobo-pr-event.json`：

```json
{
  "pull_request": {
    "title": "docs: 完善中文合并请求模板",
    "body": "新增中文模板与 AI 提交流程。验证：文档和链接检查通过。"
  }
}
```

替换为实际标题和正文后执行 `pnpm check:pr /tmp/neobo-pr-event.json`。GitHub CI 自动读取事件文件，无需手动传入路径。

## AI Agent 交付规则

完成用户授权的开发任务后，可直接提交该任务并发起 PR；已授权的步骤不重复请求确认。合并、发布和部署遵守用户授权与 [CI/CD 规则](ci-cd.md)，由维护者按规则执行。

1. 先阅读 [AI 开发入口](../AGENTS.md) 及任务相关规范，检查 `git status`、当前分支与已有 PR，保留其他人的修改。
2. 从最新 `main` 创建短期任务分支。已有任务分支则继续使用；工作区存在修改时先确认其归属，避免切换或更新分支覆盖已有工作。
3. 完成实现、review 和必要验证，默认运行 `pnpm check`，按风险追加检查；工作流修改执行 actionlint。失败时先修复并复验。
4. 根据最终实现和真实检查结果，及时同步受影响的文档、开发说明与 [迭代记录](iterations/README.md)，清理失效内容和引用，再运行文档格式、结构与链接检查。每次开发或修改均遵守此顺序，不把文档同步留到 PR 之后；细则见 [开发规范](development.md#文档同步与提交顺序)。
5. 检查最终 diff，只暂存本次任务文件，使用明确路径的 `git add -- ...`，并用 `git diff --cached` 核对。禁止 `git add .`、混入其他任务文件、丢弃已有工作或强推分支。
6. 使用中文提交说明，保留 Conventional Commits 前缀；推送任务分支，向 `main` 发起标题和正文为中文的 PR。已有对应 PR 时更新原 PR 的代码、标题和说明，避免重复创建。
7. 报告真实提交、PR 链接和已执行的验证。无远端、缺少认证、权限或网络受限时，保留本地改动及已完成的提交，说明停在哪一步，并提供可复制的中文标题与正文；禁止编造提交成功、CI 结果或 PR 链接。

PR 创建后，仍需通过 `quality` 和仓库保护规则；当前单人维护采用 0 人批准，由维护者自审并手动合并。

## 创建方式

模板合入默认分支后，在 GitHub 页面新建 PR 会自动带入正文。标题仍需按中文规范填写。

使用 GitHub CLI 时，显式传入 `--body-file` 不会自动填好模板，需先复制并填写文件：

```bash
cp .github/pull_request_template.md /tmp/neobo-pr.md
```

在编辑器中填写 `/tmp/neobo-pr.md`、删除提示文字，再创建 PR。以下以任务分支 `docs/chinese-pr-template` 为例，使用时替换为实际分支、中文标题和已填写的文件路径：

```bash
gh pr create --base main --head docs/chinese-pr-template \
  --title 'docs: 完善中文合并请求模板' \
  --body-file /tmp/neobo-pr.md
```

正文通过文件保留真实换行；标题作为单独参数传入，不把不可信标题或正文拼接成 shell 代码。没有 GitHub CLI 时可使用已有 GitHub 工具或网页提交，无需为此新增项目依赖。
